# AsterFlow ERP 作品集说明

## 项目定位

AsterFlow ERP 是一个可运行、可测试、可演示的进销存系统。它不是页面集合，而是围绕采购入库、销售出库、库存流水和权限审计构建的完整业务闭环。

## 推荐演示

1. 使用管理员账号登录，展示访问令牌刷新和主动退出。
2. 新建采购单并审核，观察库存增加和入库流水。
3. 新建销售单并审核，观察原子扣减库存和出库流水。
4. 打开库存预警和 Dashboard，说明缓存、布隆过滤器和重建锁。
5. 打开 AI 经营助手，说明 Spring AI 只读工具调用和无 API Key 时的结构化兜底。
6. 展示审计日志、Swagger、CI 和 `npm run verify` 输出。

## 关键技术决策

### 库存正确性

- 销售扣库存使用数据库条件更新，避免并发超卖。
- 订单状态、库存和库存流水位于同一数据库事务中。
- 取消已审核单据会执行对应的反向库存流水。

### Redis 与数据库一致性

- MySQL 是业务事实来源，Redis 只保存可重建缓存和会话增强数据。
- 商品、库存和 Dashboard 写路径在数据库事务提交成功后才失效缓存。
- 事务回滚不会删除或写入缓存，避免暴露未提交数据。
- Redis 不可用时读取降级到数据库，缓存 TTL 负责限制异常期间的陈旧窗口。

### 安全边界

- 后端验证 JWT 和会话状态，不依赖前端隐藏按钮。
- 管理员操作由后端角色校验保护。
- 登录和普通 API 支持 Redis 滑动窗口限流，并在 Redis 不可用时降级。
- 未知异常返回统一错误响应，不向客户端泄漏内部异常消息。

### 可交付性

- Flyway 版本化管理 MySQL schema 和演示数据。
- Docker Compose 提供带健康检查和持久化卷的 MySQL、Redis。
- CI 校验 Compose、前端测试、ESLint、生产构建和后端 `clean verify`。
- Playwright 在 Chrome 中验证登录、采购入库、销售出库、库存流水和审计日志的完整闭环。
- `npm audit --audit-level=high` 作为依赖安全门禁，README 提供真实 E2E 截图。
- `npm run verify` 在本地执行与 CI 对齐的质量门禁。

## 面试时如何描述边界

这个项目按作品集和单体应用交付标准完成。生产环境如果需要更高等级保障，可以继续增加 Testcontainers 的真实 MySQL/Redis 测试、缓存失效 Outbox、集中指标告警、Redis Cluster、容灾部署和容量压测。这些是部署规模带来的平台能力，不是当前业务闭环的未完成代码。
