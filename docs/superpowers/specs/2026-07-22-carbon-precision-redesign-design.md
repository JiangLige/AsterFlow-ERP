# AsterFlow ERP Carbon Precision 重设计规格

日期：2026-07-22

状态：已批准，等待实施计划

## 1. 目标与设计判断

本次工作是 AsterFlow ERP 的全站视觉重启。保留产品名称、业务信息架构、现有路由、字段顺序、API 合约、认证流程与权限行为，替换当前暖色编辑风界面，建立适合采购、销售与库存运营人员的精密企业工作台。

Design Read：面向采购、销售与库存运营人员的企业 ERP 重设计，采用精密工业控制台语言，视觉基础为 Carbon 风格企业界面。

设计参数：

- `DESIGN_VARIANCE: 5`：适度变化，强调清晰的信息结构。
- `MOTION_INTENSITY: 3`：静态为主，仅提供反馈型动效。
- `VISUAL_DENSITY: 8`：中高密度，优先日常操作效率。

## 2. 当前状态审计

### 2.1 技术基础

- Next.js 14 Pages Router、React 18、TypeScript。
- 全局原生 CSS 负责绝大多数页面样式。
- Tabler Icons 提供图标，Recharts 提供总览图表。
- `Layout` 负责登录保护、固定左侧导航、用户信息和退出。
- 前端请求通过现有 Next API 路由访问 Spring Boot 服务。

### 2.2 当前品牌令牌

- 暖米色页面背景。
- 深蓝固定侧边栏。
- 橙色主操作色。
- 小圆角、轻阴影和白色卡片。
- 登录页使用深色品牌区域与浅色表单区域。

### 2.3 保留内容

- AsterFlow ERP 名称和现有 Rosette 标识。该标识作为品牌资产保留，不作为业务 UI 图标使用。
- 运营总览、商品管理、供应商、客户管理、采购订单、销售订单、库存预警、库存流水、审计日志。
- 全部现有路由和页面职责。
- 登录、令牌保存、路由保护和退出行为。
- 查询、新建、编辑、审核、取消、库存调整等业务流程。
- 中文业务文案和 UTF-8 文件编码。

### 2.4 退役内容

- 暖米色、深蓝和橙色组成的旧主题。
- 固定宽度左侧导航。
- 过度依赖白色卡片和阴影的内容分组。
- 表格操作文字全部平铺造成的拥挤。
- 不统一的加载、空数据和错误状态。
- 在业务 UI 中混用 Tabler 与 Carbon 图标。

### 2.5 SEO 与兼容边界

- 不改变 URL、路由文件和主要导航名称。
- 不删除或改写现有页面元数据。
- 不更改表单字段名称、顺序或自动填充属性。
- 不更改后端接口、请求参数、响应结构和数据库。

## 3. 选定方案

采用 Carbon Precision：使用 IBM Carbon 官方 React 组件和样式体系，在其白色主题之上建立 AsterFlow 品牌层。

新增前端依赖：

- `@carbon/react`
- `@carbon/styles`
- `@carbon/icons-react`
- `sass`

Recharts 继续负责现有图表，但必须使用 Carbon 色彩、字体和间距令牌。

不混用其他组件设计系统。完成迁移后，业务界面只使用 Carbon 图标。现有 Rosette 标识属于品牌资产，可以保留；若移除 Tabler 依赖，必须先将该标识提取为具有相同外观和许可信息的静态品牌资源。

## 4. 全局应用框架

### 4.1 顶部应用栏

- 移除固定左侧栏。
- 顶部应用栏高度为 48px。
- 左侧展示 AsterFlow ERP 品牌入口。
- 中间展示一级模块：运营总览、基础资料、业务流转、系统。
- 右侧保留当前用户信息和退出操作。
- 不增加没有后端支持的通知、全局搜索或系统状态功能。

### 4.2 上下文导航

第二层导航高度为 40px，仅展示当前模块的页面入口：

- 基础资料：商品管理、供应商、客户管理。
- 业务流转：采购订单、销售订单、库存预警、库存流水。
- 系统：审计日志。

当前页面使用电光蓝底线和加粗文字标记，不使用大面积选中色块。

### 4.3 内容区域

- 常规页面最大宽度为 1440px并居中。
- 数据密集表格可以占用全部可用宽度。
- 桌面内容边距使用 Carbon spacing tokens。
- 768px 以下切换为 Carbon 移动菜单，并保持入口顺序不变。

## 5. 运营总览

### 5.1 页面头部

- 显示日期、当前用户、刷新操作和新建采购单主操作。
- 主操作文字在桌面端不得换行。

### 5.2 指标带

使用无阴影指标带展示：

- 今日销售额。
- 今日采购额。
- 待审核订单。
- 库存风险商品。

金额、数量和编码启用表格数字特性。指标来自 `/api/dashboard-summary`，不新增后端不存在的数据。

### 5.3 运营内容

- 主区域采用非对称双栏。
- 左侧为优先任务队列，包含采购审核、销售审核和库存预警。
- 右侧为采购与销售订单状态分布图。
- 下方为今日出入库动态紧凑表格。
- 加载状态使用结构一致的骨架屏。
- 空数据状态提供明确的下一步入口。
- 单个模块失败时保留其他可用模块。

## 6. 登录页

- 页面采用冷白主画布。
- 左侧为约 420px 的登录区域。
- 右侧为石墨色品牌区域，展示品牌标识、系统定位及采购、销售、库存三项能力。
- 使用 Carbon TextInput、PasswordInput、Button 和 InlineNotification。
- 保留现有默认演示账号和认证逻辑。
- 登录错误显示在表单内部。
- 登录提交期间禁用重复操作并显示加载状态。
- 移动端只保留品牌标识和登录表单，说明内容折叠到表单下方。

## 7. 列表与表格

- 所有业务列表统一为 Carbon DataTable 结构。
- 页面标题、说明和主操作位于同一标题栏。
- 查询条件进入紧凑工具栏，不使用独立卡片包裹。
- 表头固定，金额和数量右对齐，编号使用等宽字体。
- 行操作显示一个主操作，其余操作放入 OverflowMenu。
- 分页紧贴表格底部，显示总数、当前范围和页码。
- 窄屏允许包含式横向滚动，不压缩关键字段。
- 关键列在必要时固定在左侧。

状态标签映射：

- 蓝色：草稿或处理中。
- 绿色：已完成或已审核。
- 红色：已取消或存在风险。
- 灰色：停用。

语义色只表达真实状态，不作为装饰色。

## 8. 表单

- 保留字段名称、顺序、校验、请求结构和提交逻辑。
- 桌面端采用两列网格，相关字段并排。
- 订单商品明细使用可编辑数据表。
- 标签位于输入框上方，错误位于输入框下方。
- 不使用占位文字代替标签。
- 页面底部使用固定操作栏，包含保存和取消或返回操作。
- 提交期间禁用重复操作并显示清晰状态。
- 移动端降为单列并保留操作栏。

## 9. 详情页

- 顶部展示单据编号、业务状态、关键操作和返回入口。
- 主体分为基础信息、商品明细、金额汇总和操作记录。
- 使用留白、分组标题和少量分隔线建立层级。
- 审核和取消等高风险操作继续使用原有权限和接口行为。
- 确认说明必须写明业务影响。

## 10. 视觉令牌

### 10.1 色彩

- 页面背景：`#f4f4f4`。
- 主内容层：`#ffffff`。
- 主文字：`#161616`。
- 次级文字：`#525252`。
- 边框：`#c6c6c6`。
- 品牌操作色：`#0f62fe`。

页面锁定为统一浅色主题。不使用渐变、暖米色、橙色强调和装饰性彩色阴影。

### 10.2 字体

- 拉丁文字：IBM Plex Sans。
- 中文：Noto Sans SC、PingFang SC、Microsoft YaHei 回退。
- 数字和编码：IBM Plex Mono 或表格数字特性。
- 页面标题：28-32px。
- 表格和表单：以 14px 为主要字号。

### 10.3 形状与层级

- 容器圆角保持 0-2px。
- 按钮、输入框、表格和通知使用一致的高度体系。
- 不使用常规卡片阴影。
- 通过背景层级、间距和分隔线建立视觉层级。
- 焦点状态使用清晰的蓝色外框。

## 11. 交互状态与错误处理

- 按钮包含悬停、按下、禁用和加载状态。
- 页面数据包含加载、空数据、部分失败和完整失败状态。
- 页面级错误使用 Carbon InlineNotification。
- 表单错误贴近对应字段。
- 网络请求期间避免重复提交。
- 高风险操作提供确认步骤和影响说明。
- 动效时长为 150-200ms，仅使用 transform 和 opacity 表达反馈或状态变化。
- 动效遵循 `prefers-reduced-motion`。

## 12. 响应式规则

- 1440px 以上限制常规内容宽度。
- 1024px 以下压缩顶部导航间距，次要操作进入菜单。
- 768px 以下使用移动菜单，双栏区域变为单栏。
- 390px 宽度下，登录表单和主要页面操作必须可见且可用。
- 表格保留横向滚动，按钮文字不得换行。
- 不使用 `100vh`，需要满高时使用动态视口单位。

## 13. 组件边界

新增或重构的共享组件：

- `AppHeader`：品牌、一级模块和用户操作。
- `ModuleNavigation`：二级导航和移动菜单。
- `PageHeader`：标题、说明、状态和页面操作。
- `DataState`：加载、空数据和错误状态。
- `StatusTag`：业务状态到 Carbon Tag 的统一映射。
- `OverflowActions`：表格行操作菜单。
- `FormActions`：保存、取消和提交状态。

Carbon Theme 在 `_app.tsx` 统一挂载。业务页面不得自行切换主题或覆盖完整组件体系。

## 14. 数据流与后端边界

- 所有 API 地址、请求参数和响应结构保持不变。
- Dashboard 继续使用 `/api/dashboard-summary`。
- 登录、令牌保存、路由保护和退出流程保持不变。
- 设计层只重新组织展示，不生成后端不存在的指标。
- 本次改造不修改 Spring Boot 代码和数据库。

## 15. 实施顺序

1. 安装 Carbon 依赖并建立主题令牌。
2. 重构全局导航和页面框架。
3. 重做登录页和运营总览。
4. 统一列表、工具栏、表格、状态和分页。
5. 统一新建、编辑和详情页面。
6. 完成响应式、键盘操作和视觉一致性验收。

## 16. 验收标准

- `npm run build:client` 通过。
- 全部现有路由可访问。
- 登录、导航、查询、新建、编辑、审核、取消、库存调整和退出流程不回退。
- 在 1440px、1024px、768px 和 390px 宽度验收。
- 表格字段不被强制压缩，按钮文字不换行。
- 键盘焦点清楚，表单标签和错误可被辅助技术识别。
- 页面不出现旧暖色主题。
- 业务 UI 不混用 Tabler 与 Carbon 图标，Rosette 品牌标识除外。
- 加载、空数据、错误和禁用状态完整。
- 仅提交与重设计相关的前端和文档修改。

## 17. 非目标

- 不新增业务模块。
- 不修改后端、数据库或接口契约。
- 不改变导航名称和路由。
- 不引入暗色主题。
- 不增加通知中心、全局搜索或其他没有后端支持的功能。
- 不重写业务文案和数据模型。
